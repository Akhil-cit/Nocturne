# Reference Comparison: Nocturne vs. Monochrome vs. BitChord

| Feature | Nocturne | Monochrome | BitChord | Best Approach for Nocturne |
|---|---|---|---|---|
| **Runtime & Platform** | Electron (Windows 10/11) + React + TS | Web PWA (Vanilla TS/JS) | Android (Kotlin) + Web (React) + Go | Keep Nocturne's Electron + React + TS desktop-first architecture |
| **License** | Apache-2.0 compatible | Apache-2.0 | GPL-3.0 | Write original TS code; preserve Apache-2.0 attribution |
| **Music Providers** | `TracksProvider` + `LocalFileProvider` | TIDAL HiFi (domain-restricted) + `tracks.monochrome.st` | Apple/Spotify metadata + YouTube InnerTube | **Upgrade Nocturne** to unified multi-provider engine (`TracksProvider` + `iTunesProvider` for discovery/previews + `LocalFileProvider`) |
| **Track Matching & Dedup** | Basic | Basic album dedup | `trackMatcher.ts` (version/live/remix guards) | **Adopt pattern** in Nocturne `trackMatcher.ts` |
| **Lyrics Visualization** | **8 modes (Constellation primary)** + 12 backgrounds | `@uimaxbai/am-lyrics` + Butterchurn | Scrolling LRC/TTML | **Nocturne is strongest** — keep & refine |
| **Lyrics Sync & Offset** | LRCLIB + per-track offset + word timing | LRCLIB + Genius + Kuroshiro | LRCLIB + TTML + YouTube | **Nocturne** already strong; add provider attribution |
| **Desktop Integration** | Edge Lighting Overlay, Mini Player, Tray, Immersive | Media Session | Discord Presence, Party | **Nocturne** desktop integration is unique |

## Phase 11 source audit, 25 November 2026

The local comparison covers four distinct trees. Checkitout contained an already extracted BitChord-main/BitChord-main and two ZIPs. The two new *-reference directories sit beside the archives. Extraction checked Windows path components, duplicate entries, symbolic links and total expanded size before writing to fresh directories. No reference scripts or dependencies ran. BloomeeTunes had 5,156 archive entries (SHA-256 DFD0EBD2EC7FACCA7871F25509F1BF6BC178EE9DB93A0342D436C6695DDCE1F9). Bloom Factory had 371 (EB8F1CDA5896AFFE63FEF5D1225A9DE2C77718B4707D25E3421F3766B9630024). Monochrome's working tree was clean.

| Subsystem | Evidence from the downloaded source | Implication for Nocturne |
| --- | --- | --- |
| Resolver ownership | BloomeeTunes lib/services/player/media_resolver_service.dart looks for a downloaded file, parses the owning plugin ID, then dispatches getStreams. Concurrent resolutions of the same ID share a future. cross_plugin_resolver.dart scores candidates and can stop on a confidence threshold. | Keep the recording ID, origin catalog and actual audio provider distinct. Match before switching providers. |
| Regional search and radio | Bloom Factory jiosaavn/src/lib.rs dispatches track, artist, album, playlist, home, radio, search and stream methods. The local manifest actually calls the plugin **jisaavn**, with country_allowlist IN. Its client derives media URLs from protected fields and constructs quality alternatives. ytvideo and ytmusic also implement get_streams. | These sources explain the settings list. Neither source inspection nor plugin order identifies which plugin served Rathinamo in the installed BUBLLC app. No session trace or build provenance was supplied. |
| Quality and recovery | BloomeeTunes stream_quality_selector.dart filters usable results and has ordered fallbacks for each quality preference. Monochrome js/tracks-api.js getStreamUrl reports one lossless rendition even when another quality was requested. resolveTrackStream matches external tracks against its own catalog. | Select from real provider variants. Deriving a different URL or changing a badge cannot establish a new rendition. |
| Suggestions and lyrics | Bloom Factory provides three suggestion plugins. musicbrainz-suggestions/src/lib.rs uses recording queries and rate limiting. lrcnet/src/lib.rs calls LRCLIB get/search/by-ID. BitChord web/app/src/lyrics/repository.ts ranks timed sources and caches hits and misses with expiry. | Installing lrcnet would duplicate Nocturne's LRCLIB source. Local LRC sidecars and library suggestions add coverage offline. |
| Collections and discovery | Bloom Factory has distinct Spotify, JioSaavn, Apple Music and YT Music collection importers. jiosaavn-importer/src/lib.rs parses playlist and album links into collection IDs before fetching metadata. Billboard provides charts. BloomeeTunes smart_track_replacement_service.dart represents replacement confidence and affected playlists before writing database changes. | Playlist metadata import is separate from rights to play its contents. Local M3U importing can preserve order without adopting third-party private endpoints. |
| Buffering, transitions and EQ | BloomeeTunes player_engine.dart preloads a second player, swaps the active player and reapplies audio filters across crossfades. Monochrome js/player.js creates a second audio element and manages a preloaded Shaka instance. BitChord's web automix engine has deck, grid, EQ and transition scheduler modules. | Gapless timing and crossfade need two independently managed sources and listening tests. Current Nocturne uses a single audio clock for lyrics and stars. Defer engine replacement until recovery and license-aware fallback are stable. |
| Libraries and performance | BloomeeTunes stores playlists, tracks, downloads and settings through DAOs and serializes backup work. BitChord uses cached lyric lookups. Monochrome has stream-match and search caches. Nocturne has persisted JSON library state, a bounded catalog cache and user-controlled visual FPS. | Preserve existing library IDs. Avoid permanently caching provider outages, building a second metadata database or prefetching unlicensed audio. |
| Desktop and visual identity | The BitChord tree contains Kotlin multiplatform clients plus a web package with YouTube-specific playback and matching. BloomeeTunes is Flutter/Rust. No matching application provenance links either snapshot conclusively to the installed APK. | Keep the Electron renderer, constellation engine and independent desktop windows. |

### Source permissions

Monochrome ships an Apache 2.0 code license, BitChord a GPLv3 license, and the downloaded BloomeeTunes LICENSE contains GPLv2. Bloom Factory has no root LICENSE in this snapshot. No plugin source was copied. None of these code licenses establishes rights to commercial recordings. The public Monochrome audio endpoint has no third-party catalog streaming grant established in the reviewed material. Its adapter remains available for metadata. Jio documents listening through its official service and the downloaded plugin uses a private playback mechanism. Google requires preserving the official player experience. Official-service handoff retains the service's own playback conditions. [JioSaavn](https://www.jio.com/apps/jiosaavn/) · [YouTube developer policies](https://developers.google.com/youtube/terms/developer-policies)

Apple Search provides catalog IDs, storefront URLs and recording duration. Its promotional media have separate display and streaming conditions. The new catalog mapping uses metadata and supports opening the official track. Commons grants vary by file. Nocturne selects files with recognized reuse declarations and displays file-specific attribution. [Apple Search API](https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/index.html) · [Commons reuse conditions](https://commons.wikimedia.org/wiki/Commons:Reusing_content_outside_Wikimedia/en)
